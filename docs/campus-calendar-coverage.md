# 高校宣讲覆盖与采集耗时

## 2026-10-24 修正

山东大学缺席不是因为学校不在济南，而是旧配置仅接入了其网上招聘公告，未接入独立宣讲日历。另一个系统性遗漏是：高校公开列表已有时间、学校和场地，但必须等招聘正文读取成功后才能发布整条记录；正文缺失、超时或图片简章都会阻止日程出现。

现在日程事实和招聘事实分别核验：官方列表明确的日期、学校、场地可以先发布，缺少招聘正文时标为“宣讲会 / 招聘条件待核实”，不推测工作城市、报名截止、学历和毕业届别。正文补全后沿用同一个 ID，恢复招聘详情与已有企业关联规则。日期或场地变动计入内容变更；已取消场次退出日程。

- 山东交通学院公开日历接口在本次核验时最新活动仍为 2026-03-25；新闻栏目有较新的宣讲相关文章，不能把“日历无后续场次”解释成学校没有活动。此新闻渠道尚未适配。
- SDEI/BYSJY 每轮最多读取两个日程列表页；山东大学读取五个周历页；山师研究生站读取校园招聘最新一页，并核验近期通知正文中的明确活动年份、时间与地点。超过窗口的记录不宣称已覆盖。失败、退避和待补详情会保留在报告中。
- 地点不明确或线上活动不猜城市；多校区学校不按校名统一归入济南。高校的活动也可能有入校或身份要求，应查看原文确认。

## 控制耗时的方法

1. NAS 最新页巡检阶段只读取日程列表，不逐场等待正文。读取一页便写入恢复日志，进程超时也能保住已取得的日程。
2. SDEI 列表若含完整公开招聘简章，直接解析该正文，避免再次请求详情页。内容哈希和列表关键字段一起控制缓存；刷新日历不会延长旧招聘正文的核验有效期。
3. 每源每轮最多补全八条宣讲招聘详情。SDEI 优先处理已返回的正文，额外网络详情最多两条；已过日期或明确取消的活动不占详情预算。
4. 保留现有单源、分片总时间预算、共享限速和失败退避；本次没有提高并发，也没有延长 NAS 的 1200 秒采集软预算。下载、环境准备、构建时间另计。

## 生效与验收

1. 提交并推送本轮代码后，在 Actions 选择 **Daily Job Radar Pipeline → Run workflow → main**，使用正常采集，`deploy_only` 不勾选，`reuse_run_id` 留空。
2. 这次手动运行会同时派发 NAS 高校流水线。山大、山师研究生站、建筑大学走云端；中医药大学及原有 SDEI 高校走 NAS。无需改 Compose 或重建 NAS 镜像。
3. 等云端与 NAS 各自完成合并发布后，刷新网站，选择济南，查看宣讲学校选项。不要用旧运行的 Re-run 验证新代码；仅发布页面也不会补采缺失日程。
4. 查看两条流水线摘要的高校覆盖表，以及产物 `freshness-report.json` 中的 `universities`。每校会列出已接渠道、日历巡检状态、后续场次、地点待核实数量和待补详情。

本地通过 89 项 Python 定向测试、7 项前端日程相关测试，覆盖日历解析、取消与场地变更、校区城市、岗位资格隔离、正文复用、分片往返、超时恢复及调度去重；另用真实快照运行前端日程和筛选函数。真实联网核验结果保存在忽略目录 `data/talk-coverage-audit/`，不作为静态网站数据提交。
