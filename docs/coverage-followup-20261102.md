# 来源缺口、详情回补与评价覆盖 · 2026-11-02

用户要求后续缺口补齐后与卡片介绍一起提交。基线289359f；此文记录本地实现与验证，未推送、部署或写生产数据分支。不是“全国来源已全部覆盖”的声明。

## 新接入的杭州日历

杭州电子科技大学的[官方日历](https://job.hdu.edu.cn/teachin)使用公开HTML中的zlib/base64片段展示表格，先前采集器只看到了占位节点。本次直接解包精确匹配的展示片段，不运行JS、不用浏览器、不访问认证接口。限制编码长度和解压后1MB上限；日期、时间、场地、模式、同源详情路径、分页都严格校验，格式变化或登录页报错而不报空日历。每次先读取robots；404表示无声明，其它错误停止，明确拒绝则不采集。

实际独立试采两页40场，约1.39秒；11月2日起有14场，其中12场线下、2场线上。线下场地经校方公开页面证实为下沙校区后归入杭州，线上不填杭州，也不把活动所在地当岗位工作地。第3教研楼见[学院通知](https://mat.hdu.edu.cn/2024/1219/c12403a273888/page.htm)，第6/7楼见[考点公告](https://ee.hdu.edu.cn/2021/1224/c13565a150913/page.htm)，第12楼见[复试通知](https://hum.hdu.edu.cn/2026/0325/c12203a290617/page.htm)。未核实的其它楼号继续保留未知，不仅凭学校名猜城市。

沿用每轮两页：首屏必查，另一页从历史游标续读；44页历史不一次全抓。公开列表已提供活动完整时间/地点，不逐场请求招聘详情，待补详情0。本次没有把40场本地试采数据写入生产，正式显示需要新代码的正常采集。仅页面deploy_only不会凭空产生这些活动。

注册总数变为85源、29个宣讲渠道。新增源放云端universities-a，未改NAS的学校、轮转、代理、Python环境或容器。

## 详情积压的调度修复

原有排序会使持续新增的公告挤占历史未核实详情。现在每四个普通详情名额穿插一个排队至少一天的未核实详情；积压名额按最早排队先处理，任务结束后保留所有未读记录。旧队列无排队时间时从迁移开始计时，不伪造过去时间。后续宣讲仍按举办日期优先，已结束宣讲最后，不用旧积压抢占活动临近顺序。

解析为空、明确404/410至少隔24小时再读，重复失败逐步到72小时；暂时网络超时保留原短退避。已改变的列表事实仍能解除旧退避。未增加并发、请求名额或源站限速；失败也不把原有已读岗位误判下架，不删除队列或伪造核验日期。

冻结生产快照是11月2日08:09:57的23767条，待补详情3787，其中南开1967。这些数字没有因本地改调度就清零。本机公开读取南开列表及浪潮样本详情分别约0.70/0.23秒成功；这只能证明本机当前能读，不能证明云端先前Network unreachable已解除。下一轮需观察实际source报告的pending_details、detail_failed、request_diagnostic与最老排队时间，不能只看workflow绿色。

## 时长与仍存在的外部限制

- 杭电本机正常试采新增约1.4秒；云端单源180秒、分片1080秒仍为上限，慢站可能消耗该分片其它来源的剩余时间，不能保证永远只增加1.4秒。NAS仍90秒单源、1200秒分片。
- 详情改的是既有预算分配，约四比一照顾最新与积压；本轮最新详情数量可能略少，长期积压更有机会消化。不能保证每轮更快或一次清完3787条。
- 企业评价仍是独立180秒预算，不让岗位或NAS等待。新增企业不增加独立流程的时长上限，每轮按队列和冷却选择。
- 卡片单位介绍离线复用已下载正文，无新增逐岗位源站请求；但更多文字使全量浏览gzip约增加1.48MB，首片仍在256KiB内，详见卡片记录。
- 浙江工业大学公开日历域[robots](https://zjut.jysd.com/robots.txt)明确Disallow:/，记录为未接入；中国石油大学、上海交大、复旦部分日历认证，以及政务403仍需可用公开替代源或授权。看准、脉脉也未取得可接入评价渠道。这些限制没有通过代码假装修好。
