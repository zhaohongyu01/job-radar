## 对耗时的影响

|环节|实测/策略|适用边界|
|---|---|---|
|纯离线修正|0 个新增采集请求|字典扩展和城市回填不逐城市联网|
|公共线索城市查询|默认仍 54 个查询项（全国项加原城市集合）|`config/collection-city-plan.json` 已与 UI 城市字典解耦，没有随字典扩至 369 个请求|
|完整快照导出，旧代码|44.365 / 38.884 / 37.720 秒，中位 38.884 秒|同机、Python 3.12.14、同一 32,411 条来源记录，3 次分别写独立目录|
|完整快照导出，新代码|35.529 / 32.228 / 32.133 秒，中位 32.228 秒|相同输入，约快 17.1%；这是本地 CPU/磁盘环节，不是整轮 NAS 耗时|
|南开日历首轮小窗口|20 条列表、补 8 条详情，4.77 秒|一页有界实测，仍有更早页面和待补详情；不是全站完整采集|
|北大日历首轮小窗口|20 条列表，1.82 秒|官方列表已含时间场地；一页有界实测，不等于 20 场未来活动|
|NAS|每源 90 秒、采集软预算 1,200 秒保持不变|下载、环境、上传、合并、构建另计；新增两源放云端，不增加 NAS 学校请求|
|云端分片|每源 180 秒、分片软预算 1,080 秒及现有日历预算保持不变|预算内最新页优先、详情缓存、退避和轮转继续使用；网络波动仍会影响总时长|

筛选时全国地名正则只编译一次，岗位地点派生事实按对象缓存，文本缓存有上限。全量 20,823 条索引逐一核对 369 城市（包含真实筛选、排序及日程）总耗时 25.85 秒；这是**离线遍历全部城市**的审计，不是一次用户切城市耗时，页面也不会每次渲染做此全城遍历。

最大单数据资产为 14,966,297 字节，低于 25 MiB；字段补充有额外带宽成本，代表性比较中列表合计约增 7.3%、详情合计约增 6.7%。列表加载仍有界并发，详情按需读取，没有删正文换速度。

`requirements.txt`、NAS 镜像和代理配置未变：现有可用 Python 虚拟环境可继续复用，正常情况下不需要重新安装依赖或重新部署 Runner。没有执行本轮完整 NAS 生产采集，不能给出“总流程一定缩短多少分钟”的承诺。

## 来源核验与仍存缺口

- 南开：`https://career.nankai.edu.cn/recruitment/index2.html`，活动列表的日期是举办日，不误当发布日期；详情核验明确时间/地点。列表后续不抹掉已核验的同日详情场地。
- 北大：官方公开 POST `https://scc.pku.edu.cn/f/recruitmentFair/ajax_frontRecruitfair`，使用公开分页参数，不使用账户令牌。官方时间、场地先进入日程，招聘资格仍待正文核验。
- 中石大招聘公告入口本轮可读取；其独立日历接口返回明确“需要登录”，注册为 blocked 计划渠道，不伪造成功或完整覆盖。
- 复旦日历依赖认证接口，尚未取得可验证的免认证日程来源；上海试点仍未完成。列入覆盖计划，不能因城市可选就宣称已接入。
- 青岛人社官方通知栏目可访问；当前页可以没有招聘通知，已识别有效空招聘页与真实分页，不能把它误报成解析失败，也不能据此声称全市没有岗位。
- 邮储校招/社招官方栏目本轮返回空内容容器，不能证明已采齐，现明确报源站无可解析内容并保留历史，未以搜索缓存冒充当前源站数据。
- 山东交通学院、山东第一医科大学的部分旧日历渠道仍有陈旧问题；已有其它渠道与新鲜度提示不能替代这些缺口的专项修复。
