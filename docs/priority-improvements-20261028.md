## 1. 宣讲日历按预算持续补齐

发现：`nankai_talks`、`pku_talks`、`bysjy_talks` 每轮最多两页，但原先不在可续页适配器集合中；因此即使解析出了更多页，每轮也会从头读相同两页。

已将三个适配器接入现有检查点与续页机制，覆盖南开、北大、山东建筑、山东交通四个日历来源。典型连续三轮读取 `1,2 → 1,3 → 1,4`；首页持续刷新，后续页按保存游标推进，读到尾部后重新巡查。页请求失败时保留游标，下轮重试；首页快速巡检不覆盖深页进度。覆盖说明显示下次续页位置，不把两页当作全部覆盖。

BYSJY 只提供“是否还有下一页”的探测行，没有精确总页数，不能用其首页返回的 `2` 将保存游标重置到第 2 页；其游标独立处理。南开和北大仍可根据确切总页数收缩旧游标。

每轮日历列表仍最多两页，招聘详情仍最多八条；原 NAS / 云端时间预算及并发设置未变。新页面可能带来原来漏掉的详情，实际运行时间会随内容变化，但没有改为每次从头扫完整历史。山东大学的周历策略与需要完整单轮库存的企业岗位接口未改动。

这提高跨轮覆盖，不代表第一次部署就获取所有页，也不代表全国所有高校都已覆盖。受认证限制的中石大/复旦日历、邮储空栏目和部分陈旧渠道仍是独立问题，不能在界面中伪装正常。

## 2. 首批索引缩小，保留筛选依据

沿用 schema 3、内容哈希资产和现有并发上限。第一片预算由 4 MiB 改为 256 KiB，后续片仍为 4 MiB；按发布日期排序和完整记录数量不变。完整内容、搜索文件与详情分片仍保留。

将前端没有使用的五个内部字段留在详情中，不再重复放进列表：`detail_verification`、`event_verification`、`publication_note`、`detail_verified_at`、`source_published_at`。保留实际筛选和显示使用的正文摘要、工作地证据、岗位匹配字段、变更历史、来源、日期、投递链接与宣讲关联。

对同一份冻结的 10 月 26 日最终索引做拆片前后对比（21,043 条；gzip 数值是本地计算，不是线上抓包）：

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 机会数 | 21,043 | 21,043 |
| 索引分片数 | 13 | 13 |
| 首片记录数 | 1,948 | 120 |
| 首片原始字节 | 4,194,183 | 259,949 |
| 首片 gzip 字节 | 616,925 | 39,075 |
| 全部索引原始字节 | 50,337,935 | 50,106,288 |
| 全部索引 gzip 字节 | 7,509,290 | 7,496,838 |

首片 gzip 减少约 93.7%，降低首批预览下载与解析的负担。**全量加载仍约 7.5 MB 压缩 / 50 MB 解析，这次没有解决全量内存上限**，也不能把首片体积改善说成完整页面耗时降低 94%。如果首片没有满足用户筛选的岗位，预览仍要等后续片；完整统计与日程继续等待全量校验。

对修改前后完整索引运行相同前端函数：37 组筛选（城市、多城、性质、薪资、有效性、查询与变更等）、8 城日程，记录 ID、顺序及活动内容全部一致。没有以删岗位或宣讲换速度。

另用独立的完整历史状态（32,411 条来源，较早时间点，非上述 21,043 条最终样本）运行 `reproject_snapshot.py`，生成 20,823 条合并索引；全部来源 ID 与历史时间还原通过，输入未修改，网络请求为零。导出加校验本机一次共 82.982 秒；这不是 NAS 一轮采集耗时，也不是可靠的前后耗时比较。

## 3. 日程筛选减少占屏

城市与学校并排保留；“全部 / 今天 / 未来 7 天”用快捷按钮。自选日期、形式、类型、包含异地线上、我的日程放入“更多筛选”。折叠后仍显示生效条件，避免用户不知道为何结果为空；“清除附加筛选”保留城市和学校。

日程收藏、改期提示、原文入口与 ICS 导出不变；不删除未知信息或把不确定岗位说成已确认。一场活动时取消原先强制 460px 的列表高度，长日程仍可滚动。修正导出/展开按钮复用深色主题浅文字导致在白色卡片上几乎不可见的问题，浏览器检查文字对比度至少 4.5:1。保留当前界面主题，未启用旧 `workspace.css`。

## 生效步骤与后续范围

获准提交推送后，应先通过 CI，再由最新代码完成正常采集、合并与导出，最后部署。只重新部署旧 JSON 不会产生 256 KiB 首片，也不会推进日历游标；无需为这三项改动重新部署 NAS 代理或 Runner 容器。

本轮不包含订阅后端、个人匹配推荐、企业独立页，也没有完成全文索引进一步瘦身。后续应先设计保留薪资/地点/资格/变更语义的精简列表契约，再将摘要和全文真正按需加载，并沿用同数据筛选一致性与真浏览器测试；不能直接截断摘要或丢掉 `position_matches`。数据解析率与认证受限来源继续单独跟踪，不能标记为“全部问题已解决”。
