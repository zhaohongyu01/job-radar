# 评价归属与覆盖改进（2026-10-30）

用户批准先修内容归属，再扩展企业页发现、核验分页和改进展示。本批未提交推送、部署或写真实数据分支；个人日历、个人匹配、关闭页面后通知继续暂缓。保留工作区原有修改。

## 实现

- 员工体验增加 `attribution: target | uncertain`。正文明确关联当前企业的任职/实习陈述或明确的企业体验标题才支持归属；比较前公司、跳槽及无法确认对象的内容进入待核对。规则仍是保守分类，不是身份认证。
- 待核对内容保留原日期、短摘句与原文，不计员工体验数量、正负主题或评分；面板新增单独入口。模型未直接用于生成企业分数，原评分门槛保留。
- 老状态迁移为normalizer 3：旧摘句不足以重新认定完整正文归属，保留记录并暂停评分。新构建也对未带归属字段的旧体验保守处理；不刷新源站读取时间。
- 默认自动选择有内容的近期栏目；只有历史内容时明确显示全部历史。用户仍可手动指定内容类型和时间，个人草稿保持不变。
- 在独立180秒预算内，最多3个公开岗位企业名称进入25秒有界候选发现。搜索结果只接受固定牛客企业路径，再读取企业页核对准确名称；歧义、无效或不可读不建立对应。结果按名称冷却24小时，已验证映射保存在采集状态并参与下一轮队列与优先级；不上传本机个人意向、收藏或备注。
- 候选发现采用公开Bing RSS；本机实测返回无关域名，已被过滤，**没有据此扩充企业覆盖**。搜索入口的实际可用性仍是限制；候选流程测试成功不等于已找到真实新企业。
- 每栏目最多探查两页，以新记录ID判断是否前进。重复页、空页、分页不可用分别记录，不声称完整抓取；第一页成功的数据不会被第二页故障丢弃。讨论栏目失败仍允许尝试独立面经栏目，连续3个页面失败停止批次；部分失败按4小时冷却恢复，完整成功才使用48小时缓存。

主要修改：`scripts/collect_reputation.py`、`scripts/build_reputation{,_queue}.mjs`、`config/reputation-sources.json`、`lib/reputation.ts`、`components/reputation-{panel,coverage}.tsx`。
