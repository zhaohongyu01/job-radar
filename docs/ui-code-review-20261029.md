# 界面功能与代码审查（2026-10-29）

审查基线为 `af79dd4`，并包含审查时已有的 `components/job-card.tsx`、`app/feature-updates.css` 未提交修改。`AI_HANDOVER.md` 亦已有使用者修改，本轮未覆盖。这次进行代码审阅与隔离浏览器复现，没有修改业务代码、提交、推送或触发采集。

结论：紧凑化方向可以保留，但个人记录的一致性应优先修复。共确认 **7 项缺陷：3 项 P1、4 项 P2**。未发现可据此直接断言的 P0 问题。以下区别于新功能建议，均有具体触发与实际复现结果。

> 后续进展：使用者已批准修复，本报告的7项缺陷已在本地完成修复并验收。详见 [修复及验证记录](ui-fixes-20261029.md)；下方保留的是修复前的审查证据，不再作为当前待修列表。

## 1. [P1] 多标签页写入会丢失另一页刚保存的个人记录

位置：`app/page.tsx:260–264`，初始读取在 `346` 行起；当前页面未监听个人记录键的 `storage` 更新。

复现：同一个隔离浏览器开两个标签页；第一页收藏岗位甲，第二页随后收藏岗位乙。第二页未同步第一页的收藏，以旧的 `personalRef` 整表覆盖存储。实际存储最后只剩乙，甲的记录消失；第一页还可能继续显示已收藏，造成与持久化数据不一致。

建议：监听个人记录的跨页变更，及时同步显示与引用；保存时将具体变更合并到最新持久化记录，避免从过期 React 副本整表覆盖。相同岗位同时编辑时需要版本/冲突处理。

验收：两页按任意顺序收藏、标已读、修改不同岗位备注，最终记录均保留，页面与刷新后结果一致。

## 2. [P1] 详情表单会把刚标记的“已投递”撤销

位置：`components/application-tracker.tsx:8–12`、`23–24`；组件在 `components/detail-drawer.tsx:462` 仅按岗位 ID 设置 key。

复现：打开尚未投递的岗位详情，点击上方“标记已投递”，然后只在跟进表单补备注并保存。表单的阶段、投递时间由首次 `useState(record...)` 初始化，之后未随快捷操作更新；此时表单仍是 `planned`，保存把 `applied` 改回 false，同时把刚记录的投递时间清成 null。

建议：统一快捷操作与表单的状态来源；保存时只提交实际编辑的字段，并处理外部更新与未保存草稿的冲突。不要简单在记录更新时间变化时强制重新挂载，导致用户已输入的草稿被清空。

验收：标记已投递后保存备注仍保持已投递及原投递时间；已有面试阶段、下次安排与未保存草稿也不得被无关操作重置。

## 3. [P1] 导入旧备份会覆盖较新的收藏、隐藏和阅读状态

位置：`lib/personal-records.ts:40–46`；导入确认说明在 `app/page.tsx:1402`。

复现：本机10月29日记录是 `saved=true, hidden=false`，备份10月28日记录是 `saved=false, hidden=true`。选择“合并，保留本机冲突备注”后，备注与更新时间保留本机新值，收藏与隐藏状态却变成备份旧值。当前代码先展开备份覆盖所有字段，仅对 `PERSONAL_DETAIL_FIELDS` 恢复较新值；`saved/hidden/readAt` 不在保护范围。

建议：对全部个人状态定义一致的时间与冲突规则；明确的 false/null 仍应作为用户取消操作保留。对无法比较时间的旧版备份，提供符合界面说明的冲突处理，不能静默覆盖。

验收：较旧备份不撤销较新收藏、恢复已隐藏记录、隐藏新恢复的机会或回滚阅读状态；新版本取消操作和 v1/v2 备份兼容均需验证。

## 4. [P2] 手机提醒浮层超出左侧屏幕，标题与正文被裁掉

位置：`app/feature-updates.css:339–344`，提醒容器相对定位于按钮。

复现：390px 视口，打开顶部“提醒”。换行后的按钮位于看板中部，浮层按按钮右侧对齐，实际左坐标为 **-98.5px**，宽320px。限制最大宽度不能限制横向位置，约98px内容在屏幕外。

建议：使用带视口碰撞避让的浮层/Portal，或在窄屏采用明确的左右边距；同时检查页面滚动、缩放、键盘焦点及关闭入口。

验收：320/360/390/768px视口，含0条和多条提醒时，浮层的标题、开关、关闭按钮及每条内容均可见可操作。

## 5. [P2] 多城市提示不换行，撑宽手机列表

位置：`app/feature-updates.css:674`；标签文本拼接在 `components/job-card.tsx:121–123`。该样式来自审查时尚未提交的卡片紧凑化修改。

复现：390px手机选择15个工作城市，岗位确实覆盖这些城市。“工作地含……”标签宽约536px，文档宽度变为 **571px**，产生横向滚动并挤出可视区域。

建议：限制标签宽度并允许换行，或显示少量匹配城市与“另N城”，同时提供查看完整匹配城市的入口。继续保留“本条实际匹配城市”的语义，不能改成所有已选城市。

验收：2/5/15个城市、长名称与全国覆盖来源在卡片/表格/手机筛选后均无页面横向溢出。

## 6. [P2] 纯日期截止在当天08:00后从提醒消失

位置：`components/personal-reminders.tsx:73–74`；已有统一日期处理函数为 `lib/opportunity-validity.ts` 的 `deadlineTime`。

复现：将收藏岗位的截止设置为受支持的 `2026-10-29`，北京时间当日12:00查看。卡片/顶部显示“今日截止”，提醒弹窗却显示暂无临期收藏。`Date.parse('2026-10-29')` 是UTC零点，即北京时间08:00；小于当前时间后被过滤，和按中国时间当天结束判断的列表不一致。

建议：提醒、待投队列排序统一复用日期精度处理，避免同一截止在不同功能中出现不同结果。

验收：纯日期在08:00、12:00、23:59和次日00:00的边界正确；含明确时间/时区的截止仍精确生效。

## 7. [P2] 全文请求短暂失败后，连续更换关键词不会恢复搜索

位置：`app/page.tsx:501–515`，effect依赖的是 `needsSearch` 布尔值；搜索错误显示在 `981` 行。

复现：第一次全文分片返回503，后续请求已可返回200。将关键词“甲”直接改为“乙”，请求次数仍只有一次，页面持续显示“数据分片读取失败”，没有岗位结果。非空词之间切换不会改变依赖，也没有单独的全文重试入口。清空搜索再输入或全页刷新可以恢复，普通换词不会。

建议：提供明确的全文重试动作和独立重试状态，开始新尝试时清理旧错误；可使用有界自动重试，但不要让每次输入都无条件重新下载全量全文。

验收：503后网络恢复，点击搜索重试即可显示结果，无须重新下载列表；成功缓存复用，取消请求及跨快照迟到响应的保护保持。

## 功能边界与后续顺序

建议顺序：先修个人记录的三项P1，再修手机浮层/长城市、日期提醒与搜索重试，随后补上对应回归场景。原界面和精简列表改进可以保留。

另有两处产品说明需要明确：顶部“待投递”入口实际打开全部收藏，个人列表默认仍按最新发布排序，和页面“按截止时间排列”的文字不一致；提醒浮层引导用户“导出日历”时，当前导出内容仅为校园活动，不包含岗位截止和个人跟进。它们不属于本报告7个浏览器复现缺陷，但应在下一批功能说明/交互完善时处理，避免用户误以为已有待投专用队列或手机投递提醒。

订阅推送、企业页、个性化推荐仍是未实现功能。当前这轮审查不以功能扩张代替既有状态一致性修复。
