## 数据与冲突规则

- 存储键和备份格式不变，继续兼容 v1/v2/v3。网址仍只存筛选条件和岗位 ID，不包含备注、投递或收藏记录。
- 两份记录都有可区分的更新时间时，较新记录的已有字段优先；未包含的字段保留合并能力。同一时刻采用不同时区格式表达，也视为时间相同。
- 无法区分新旧时，确认按钮决定冲突字段保留哪一侧；默认保留本机。选择备份优先也不会覆盖具有明确较新时间的本机状态。
- `readAt:null` 表示明确取消已读。无关字段的保存不能删除该标记，否则同岗位旧来源的已读状态会再次生效。
- 表单只提交实际编辑字段；提交时还会在锁内核对这些字段是否发生迟到更新。草稿不会因个人记录更新时间变化而强制重建组件。
- 验证过的 Edge 支持 Web Locks，可以串行处理同时写入。缺少该 API 的旧浏览器退回保存时重新读取；该兼容路径不承诺跨页面同时写入的原子性。
- 本轮保护对象是岗位个人记录。没有将活动收藏、筛选方案等所有存储统一迁移成新的数据库，也没有增加账号或云端同步。

## 影响与剩余边界

本轮只变动浏览器状态、提示与布局，不改采集来源、并发、限速、网络代理、NAS镜像或 Actions。因此不会增加采集耗时，也不需要重新部署 NAS 容器。网站更新需要后续提交、推送并完成网页部署后才会在线上生效。

审查中另外提到的“待投递入口实际打开全部收藏”、个人列表的默认排序、订阅推送、企业页等产品项不属于本轮7项修复。提醒说明已改清楚：页面关闭后不推送，校园活动可导出日程，岗位截止和个人跟进尚未包含在该日历导出中。本轮没有核验生产数据的新鲜度或来源覆盖，不能据此宣称全国采集完整。
